# Session Decision Summary: Web Transport Implementation

Date: 2026-07-11 15:11

## Context

The desktop app (Go WebView + Electron) was removed in the previous commit. The user wanted a minimal web transport that mirrors the console output — terminal-like rows in a browser, SSE streaming, no chat bubbles, no frameworks. Five simple controls (mode, model, favorite star, reasoning toggle, clear) replace keyboard shortcuts that don't work in browsers (Tab, Ctrl+\, Ctrl+F/R, Ctrl+T).

## Changes Made

- **`internal/web/`** (5 new files, ~41 KB):
  - `doc.go` — package documentation
  - `renderer.go` — HTML rendering engine: `renderLineHTML`, `renderInlineHTML`, `toolLineHTML`, `separatorHTML`, `assistantContentHTML`, `parseToolResult`. Mirrors the console ANSI renderer using CSS class names (orange, blue, green, purple, red, ctx, reasoning) instead of escape codes.
  - `handler.go` — `runtime.Handler` implementation converting LLM callbacks into SSE block events. Handles `OnContent`, `OnToolCall`, `OnToolResult`, `OnReasoning`, `OnUsage`, `OnSystem`, `OnMaintenanceCall`, `OnMaintenanceResult`, `OnStreamPhase`, `RequestSudoApproval`.
  - `server.go` — HTTP server with SSE hub, block management, and 8 endpoints (`/`, `/events`, `/input`, `/mode`, `/model`, `/toggle-favorite`, `/toggle-reasoning`, `/clear`). SSE events: `block`, `status`, `config`.
  - `page.go` — single-page HTML app: Monokai dark/light CSS themes, top bar with 6 controls, transcript area with typed rows, footer with status and composer. Vanilla JS: EventSource SSE streaming, diff-based block rendering, auto-scroll, form submission for controls. All inline, zero external dependencies.
- **`main.go`** — added `-web` flag, `runWeb()` function, import of `internal/web`
- **`prompts/transport.web.md`** — updated from "web chat interface" style to "web terminal-like interface" style matching the console transport prompt

## Decisions And Rationale

- **SSE, not WebSocket.** The web transport is read-heavy (streaming LLM output to browser) with minimal client→server traffic (POST requests for input/controls). SSE is simpler, works through proxies, auto-reconnects, and requires no upgrade handshake.
- **Inline HTML template, no templates package.** The entire page is one Go string constant. No `html/template`, no separate HTML/CSS/JS files. This keeps the binary self-contained with zero external assets, matching the console's embedded approach.
- **Server-side rendering of Markdown → HTML.** The Go server converts Markdown to styled HTML before sending SSE blocks. The browser just appends pre-rendered `<div>` rows. This avoids shipping a Markdown library to the client and keeps the JS minimal (no marked.js, no highlight.js).
- **Diff-based block rendering in JS.** The client stores `lastBlocks` and only appends/replaces/rebuilds rows when the block list changes. This prevents full transcript re-renders on every SSE event.
- **Controls replace keyboard shortcuts.** Tab → mode dropdown. Ctrl+\ → model dropdown. Ctrl+F/R → star button. Ctrl+T → reasoning checkbox. `/clear` → clear button. Theme toggle is a browser-only bonus (localStorage) since the console has no theme toggle.
- **No `/cd` button.** The user explicitly said "ce merge ca text, nu se implementează buton" — workdir changes remain a text command.
- **Sudo not supported.** `RequestSudoApproval` returns `false, ""` — web has no secure password flow.
